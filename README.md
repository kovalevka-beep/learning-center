# Учебный центр — мини-сайт для практики Яндекс Метрики

Готовый сайт на HTML/CSS/JS. Не нужны сборка, установка библиотек или серверная база данных.

## Что есть на сайте

- Каталог: два материала и два теста, общий прогресс.
- Карточка материала: описание и внешняя ссылка, которая открывается в новой вкладке. Обычный клик, нажатие Enter или средняя кнопка мыши помечают материал как пройденный. Открытие через контекстное меню браузера не фиксируется.
- Карточка теста: описание и переход в «Практикум» в той же вкладке; статус становится «В процессе».
- «Практикум»: имитация платформы с кнопками «Завершить: пройдено» и «Завершить: не пройдено». После выбора результат сохраняется, появляется ссылка в каталог.
- Повторная попытка заменяет предыдущий результат. В общий прогресс входят только позиции со статусом «Пройдено».
- Сброс прогресса с подтверждением.

«Практикум» — отдельная страница того же сайта, визуально оформленная как другая платформа. Это не настоящий внешний домен и не настоящий экзамен. Поэтому страницы могут обмениваться результатами через localStorage. Для реальной внешней платформы потребуется поддерживаемая ею интеграция; просто получить чужой результат по ссылке невозможно.

Данные сохраняются только в текущем браузере для адреса этого сайта. Другой браузер, устройство или очистка данных начинают обучение заново. Личного кабинета и общей статистики обучающихся здесь нет. Не вводите реальные персональные данные: они для стенда не нужны.

## Файлы

```text
learning-center/
├── index.html          # главная и каталог
├── item.html           # карточки: item.html?id=analytics и т. д.
├── platform.html       # имитация внешней платформы
├── assets/
│   ├── style.css       # оформление и мобильная версия
│   ├── data.js         # названия, описания и ссылки
│   ├── config.js       # номер счётчика Яндекс Метрики
│   └── app.js          # переходы, статусы, прогресс, события
├── .nojekyll            # отключение обработки Jekyll
└── README.md           # эта инструкция
```

Все пути относительные, поэтому сайт работает и в подпапке GitHub Pages.

## Публикация через браузер — без команд

1. Скачайте архив проекта и распакуйте его на компьютере. В распакованной папке найдите `index.html` и папку `assets`.
2. Войдите в [GitHub](https://github.com/). Нажмите **+ → New repository** (новый репозиторий).
3. Назовите репозиторий `learning-center`, выберите **Public** и нажмите **Create repository**. Публикуются только демонстрационные файлы из архива.
4. На странице пустого репозитория нажмите **uploading an existing file**. Если репозиторий уже содержит файлы, используйте **Add file → Upload files**.
5. Перетащите **содержимое** распакованной папки: `index.html`, `item.html`, `platform.html`, `README.md`, `.nojekyll` и папку `assets`. Не загружайте ZIP и не помещайте всё во вложенную папку `learning-center`: файл `index.html` должен оказаться прямо в корне репозитория. Папку `assets` перетаскивайте целиком, сохраняя её структуру.
6. Нажмите **Commit changes**. Если система просит выбрать ветку, используйте `main`.
7. Если скрытый файл `.nojekyll` не загрузился, нажмите **Add file → Create new file**, укажите имя `.nojekyll` и сохраните пустой файл через **Commit changes**.
8. Откройте **Settings → Pages**. В разделе **Build and deployment** выберите **Source → Deploy from a branch**.
9. В **Branch** выберите `main`, рядом — **/(root)**, затем нажмите **Save**.
10. Дождитесь завершения публикации. Проверить ход можно на вкладке **Actions**; обновите **Settings → Pages**, где появится ссылка и кнопка **Visit site**.
11. Адрес будет вида `https://ВАШ-ЛОГИН.github.io/learning-center/`. Пользуйтесь адресом, который показывает GitHub. Это ссылка на сайт; адрес `github.com/...` открывает исходные файлы.

Официальная инструкция: [Настройка источника GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

### Если что-то не открылось

- **404**: проверьте завершение публикации в Actions, ветку `main`, папку `/(root)` и наличие `index.html` в корне. Имя файла должно быть строчными буквами.
- **Нет оформления**: проверьте, что папка `assets` загружена целиком и не переименована.
- **Старая версия**: дождитесь новой публикации и обновите страницу сочетанием Ctrl+F5.
- **Не сохраняется прогресс**: разрешите браузеру хранить данные сайта. В приватном режиме они могут удаляться после закрытия окна.

## Проверка после публикации

1. Откройте каталог: первоначальный прогресс — 0 из 4.
2. Откройте материал: сам просмотр карточки не завершает его.
3. Нажмите «Перейти к материалу»: откроется справка в новой вкладке. Вернитесь в каталог — материал пройден, прогресс 1 из 4.
4. Откройте тест и перейдите в «Практикум». Если вернуться без результата, тест останется «В процессе».
5. Завершите тест как «Не пройдено», вернитесь в каталог: прогресс не увеличился.
6. Начните новую попытку и завершите как «Пройдено»: прогресс станет 2 из 4.
7. Обновите страницу: результаты сохранятся. Проверьте «Сбросить прогресс» и отмену подтверждения.

Для проверки сохранения используйте опубликованный сайт. Двойной щелчок по `index.html` позволяет посмотреть интерфейс, но обмен сохранёнными данными между локальными файлами зависит от браузера.

## Изменение материалов

Откройте `assets/data.js` на GitHub, нажмите значок карандаша. Поля: `id` — уникальное имя латиницей, `type` — `material` или `test`, `title` — название, `description` — краткое описание, `details` — текст карточки, `duration` — длительность, `category` — категория, `url` — внешняя HTTPS-ссылка для материала. Сохраняйте кавычки и запятые. После **Commit changes** дождитесь повторной публикации.

Не заменяйте ссылку теста произвольным внешним адресом: текущая имитация сохраняет результат на странице `platform.html`. Для своих материалов меняйте поле `url`.

## Подключение Яндекс Метрики

По умолчанию счётчик отключён. Сайт работает без него.

1. Создайте счётчик в [Яндекс Метрике](https://metrika.yandex.ru/), указав опубликованный адрес сайта.
2. Скопируйте числовой номер счётчика.
3. На GitHub откройте `assets/config.js` и замените `window.METRIKA_ID = 0;` на строку со своим номером, например `window.METRIKA_ID = 12345678;`. Это пример, используйте собственный номер.
4. Сохраните изменение и дождитесь публикации. Загрузчик счётчика уже подключён на всех трёх страницах: второй раз вставлять код не нужно. Вебвизор по умолчанию не включён.
5. В Метрике создайте цели типа **«Целевое событие» / JavaScript-событие** с точными идентификаторами ниже.

| Идентификатор | Когда отправляется |
| --- | --- |
| `card_open` | Открыта корректная карточка материала или теста |
| `material_open` | Нажата внешняя ссылка материала |
| `test_start` | Нажат переход к тесту из карточки |
| `test_pass` | Выбран результат «Пройдено» |
| `test_fail` | Выбран результат «Не пройдено» |

С событиями передаются `item_id` и `item_type`. Повторные открытия и попытки могут отправлять события снова: число событий не равно числу уникальных завершённых материалов. Сброс прогресса очищает только локальные статусы, не историю Метрики. Блокировщики и настройки браузера могут препятствовать отправке событий.

Для цели на посещение страницы можно использовать условие «URL содержит» со значением `item.html?id=analytics` или `platform.html?id=onboarding`. Переход на платформу не означает успешное завершение — для успеха используйте `test_pass`.

Документация: [Целевое событие](https://yandex.ru/support/metrica/ru/general/goal-js-event), [Метод reachGoal](https://yandex.ru/support/metrica/ru/objects/reachgoal).
